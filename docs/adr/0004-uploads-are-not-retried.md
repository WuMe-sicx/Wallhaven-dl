# 上传失败不重试

下载失败会重试一次（`_get_image`），上传却不会——这个反差是刻意的，不要「修」。

`POST /api/v2/upload` 不幂等：如果第一次其实已经成功、只是响应在网络上丢了，重试就会在相册里多出一份。而漏传并不会永久丢失——每次上传前都会拉取相册里已有的文件名并跳过重复，所以**「下次再运行一遍」本身就是可靠的重试机制**，且不带重复风险。

唯一的例外是 429：那是请求被拒绝、根本没被处理，退避后重试安全。

## Consequences

- 单次运行结束时可能有若干张显示为失败，这是正常的；下次运行会自动补上。
- 这条依赖「按文件名去重」这一机制。若将来改成不查已有文件名（比如为了省请求），补传能力随之消失，那时才需要重新考虑重试。
