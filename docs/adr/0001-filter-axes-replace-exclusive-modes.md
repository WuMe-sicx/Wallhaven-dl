# 用可叠加的筛选轴取代互斥的下载模式

原先的入口是三选一的模式（category / latest / search），但 wallhaven search API 的各个查询参数本来就能自由组合——互斥是我们代码的限制，不是 API 的。现改为若干条可同时取值的筛选轴，于是「月榜 + 动漫 + 竖屏」这类组合得以表达。轴的**呈现方式**分两种：内容类相关的做成可多选的具名预设（「动漫」「风景」），尺寸、纯度、排序则各占一个独立提问。两者都只是问法，不影响轴之间可自由叠加这一核心。

## Consequences

- 三个旧入口不再存在。它们的能力没有丢：`category` → 内容类别轴与纯度轴，`latest` → 排序轴的「月榜」，`search` → q 轴的自由关键词。
- 排序轴是唯一真正互斥的轴；其余轴各有合并算子（q 空格 AND、categories/purity 位或、ratios 逗号）。同轴多写按算子合并，未声明算子的轴重复写入即报错。
- 尺寸轴做成单选（手机端 / 电脑端 / 不限）。portrait 与 landscape 的并集等于不筛选，单选让这个退化组合在结构上无法表达，因此代码里不保留任何退化检测——需要时再按当时的实际组合加回。
- 落盘目录按选中的内容预设名拼接，尺寸接在末尾（如 `动漫+手机端/`），因此同一张图可能出现在多个分组目录下。这是有意的：目录要完整代表一次筛选，跨目录不去重。
